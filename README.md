# ポン！ — 早押しクイズ

Node.js 24 / npm。部屋を作成し、招待リンクまたは6桁コードで参加します。

```sh
npm ci
npm start
# 別ターミナル
npm test
```

既定ポートは3000。`PORT`で変更できます。公開運用はHTTPS対応のリバースプロキシとWebSocket対応のNode.jsホストを使用してください。

## 遊び方

- 作成者が司会者。イントロ、ボタンのみ、ノーマルの3モードから選択します。
- 司会が開始すると受付開始。最初にサーバーへ到着した早押しを確定し、タイマーとイントロ再生を停止します。
- 正誤判定は司会が行い、参加者の＋/−で採点。リセットで再受付、次の問題で進行します。司会も押下できます。
- イントロはYouTubeプレイヤーの実際の再生開始イベントでタイマーが開始します。音声は司会端末のみ。同室で使うか、通話アプリで音声共有してください。全参加者端末での音声同期は実装していません。
- 問題・答え・得点操作は司会向け。参加者には答えを公開するまで送信しません。ただし動画URLは参加者にも配信されるため、厳密な不正防止用途には向きません。

## 問題の取り込み

CSV（UTF-8）のヘッダーは `title,answer,url,start`。日本語の `問題,答え,URL,開始秒` も対応。ノーマル問題ではurlを空にできます。イントロではYouTubeの動画URLを指定。startは開始秒です。最大500問、CSVは500KBまで。画面からCSV形式で編集できます。

Googleスプレッドシートは公開したシートURLを入力（通常の共有URLは閲覧可能な公開設定が必要）。非公開シートの認証には対応していません。gidでタブを指定できます。

YouTubeの公開・限定公開プレイリストURLから動画ID一覧を取り込めます。APIキー不要ですが、ブラウザでの埋め込み制約により取得・再生できないリストや動画があります。その場合はCSVを使用してください。曲名と答えは自動取得しないため、取り込み後に編集して保存します。再生の自動開始はブラウザのポリシーに依存します。司会の開始ボタンを押してください。

## 制限

部屋・問題・得点はメモリに保存し、サーバー再起動で消えます。退出・切断すると参加者とその得点は削除されます。司会が退出すると次の参加者に司会権限を渡します。全員退出した部屋は削除されます。再接続は部屋に入り直してください。1部屋30人まで。通信遅延を補正する競技用途、公衆向け大量アクセス、永続保存、ログイン、部屋のパスワードは未実装です。

## 開発

`npm run dev` はNodeのwatchモード。`npm test` は実際のWebSocketクライアントで部屋参加、同時押下、権限、採点、タイマー、答えの公開を検証します。フロントはビルド不要のHTML/CSS/JavaScriptです。

クラウド環境の外部通信先に `docs.google.com`, `*.googleusercontent.com`, `www.youtube.com`, `www.youtube-nocookie.com`, `s.ytimg.com`, `i.ytimg.com`, `*.googlevideo.com` が必要です。設定の下書きを保存済みですが、実通信への適用・公開は環境設定側で行います。`npm start` はNode.jsの `--use-env-proxy` を使用して、既存の環境プロキシを尊重します。

## GitHubからデプロイ（Render）

`render.yaml` を同梱しています。Renderにログインして「New → Blueprint」からGitHubの `ns25350/quiz` を連携し、`main` ブランチの設定を読み込んで作成してください。作成時にプランと料金を確認してください。デプロイ先URLを参加者に共有すれば、同じサーバーの部屋へ参加できます。GitHub PagesはNode.jsサーバーを実行できないため、この構成には使えません。

ビルドで依存関係をインストールしてテストし、本番用依存関係だけを残します。Renderが割り当てる `PORT` を使用し、`/health` をヘルスチェックに使います。GitHubの `main` 更新で再デプロイするよう、Renderの自動デプロイ設定を有効にしてください。

無料プランは一定時間アクセスがないと休止する場合があり、次回の起動に時間がかかります。再起動・再デプロイで部屋は消えます。部屋の状態はメモリ保存なのでインスタンス数は1台で運用してください。複数台で運用する場合はRedisなどによる共有が必要です。
