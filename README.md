# ポン！ — 早押しクイズ

Node.js 24 / npm。部屋を作成し、招待リンクまたは6桁コードで参加します。

```sh
npm ci
npm start
# 別ターミナル
npm test
```

既定ポートは3000。`PORT`で変更できます。公開運用はHTTPS対応のリバースプロキシとWebSocket対応のNode.jsホストを使用してください。

## 遊び方

- 作成者は運営専用の画面へ、参加者はプレイヤー専用の画面へ移動します。イントロ、ボタンのみ、ノーマルの3モードから選択します。運営は競技の参加者・得点一覧に含めません。
- 運営の大きなスタートタイルで受付開始。最初にサーバーへ到着した早押しでタイマーとイントロ再生を停止します。その後も未押下のプレイヤーは押せ、2番目以降の順番を記録します。1人1ラウンド1回。順番はサーバーへの到着順です。停止後の押下時間も元の開始時刻からの経過時間です。
- 運営は最初に押した人・押下順・全員の得点をタイル画面で確認できます。＋/−で採点、リセットで同じラウンドを準備し直し、次へで次の問題へ進みます。ボタンのみモードでも次へで新しいラウンドを準備できます。開始はスタートを押してください。運営は早押しできません。
- プレイヤーは回答台で全員の得点と押下順位を確認できます。画面下に透け感のある早押しボタンを浮かせ、タップは指を置いた時点、Spaceはキーを押した時点で送信します。答えの公開後は押下受付を終了します。
- イントロは運営のYouTubeプレイヤーの実際の再生開始イベントでタイマーが開始します。初期設定では運営端末のみ再生します。運営が「プレイヤー端末でイントロ曲を再生」を許可すると、参加者も自分の端末で曲を聞けます。
- 問題・答え・得点操作は運営向け。参加者には答えを公開するまで送信しません。プレイヤー端末でのイントロ再生を許可すると動画URLも配信され、YouTubeの表示から曲名が分かる可能性があります。厳密な不正防止用途には向きません。

## 採点と設定

運営の最初の早押しタイルに正解・不正解ボタンがあります。初期値は正解+1点、不正解0点。運営の「設定」から点数を変更できます。同じ判定を繰り返しても重複加点しません。判定を変更すると以前の判定分を戻し、新しい点数を適用します。手動の＋/−による調整はそのまま残します。リセット・次へで判定をクリアしますが、得点は保持します。

運営の設定では、プレイヤーの早押し効果音、イントロ曲の端末再生、全員の押下順記録、プレイヤー側のタイマー・得点表示を切り替えられます。先着1人のみの設定にすると、2人目以降は押せません。得点を非表示にした場合、プレイヤーへの配信でも得点を伏せます。設定はこの部屋にのみ反映し、部屋とともにメモリに保存されます。

プレイヤー画面はPC・スマホとも左右に同じ幅でタイマーと回答台を配置します。「設定」から上下配置にも変更できます。ボタンの文字・アイコン・形・色・透明度・サイズ・位置、透過PNG等の独自画像（500KBまで）、効果音・音量を設定できます。設定と画像はブラウザのlocalStorageに自動保存します。他の端末には同期しません。画像はサーバーに送信しません。

早押し効果音はWeb Audioで鳴らします。参加・部屋作成などの画面操作後に再生可能になります。運営が許可し、各端末で「効果音を聞く」がオンになっている場合に、サーバーが受け付けた新しい押下だけを鳴らします。運営が禁止すると効果音の送信・再生を止めます。

イントロ曲の端末再生は効果音と別の設定です。運営の「設定」で「プレイヤー端末でイントロ曲を再生」をオンにし、各プレイヤーが「この端末で聞く」を押します。運営の開始・一時停止・再開、最初の早押しによる停止、リセット・次の問題に連動します。途中参加では現在の再生位置から読み込みます。各端末で曲の音量とミュートを調整でき、運営の許可をオフにすると曲を停止します。曲の音量だけをブラウザに保存し、音声の有効化は参加のたびに行います。

YouTubeの自動再生制限により追加のタップが必要な場合があります。その場合は「再生を有効にする」またはYouTubeの再生ボタンを押してください。端末の読み込み時間・通信遅延による再生のずれを完全にはなくせません。再生中は一定以上のずれを補正します。同室では複数端末の音が重なるため、運営のみで再生するかイヤホンを使ってください。

回答者画面のイントロ再生バーは、再生中に動き、早押し・一時停止で停止します。端末再生を有効にした場合は、その端末で実際に再生できている状態に連動し、読み込み待ち・ミュートも表示します。端末再生を使わない場合は運営の再生状態を表示します。YouTubeの音声を解析した周波数スペクトルではなく、再生状態を表すアニメーションです。OSの「動きを減らす」設定にも対応します。

## ゲームルール

運営の「設定」でゲーム開始前に選択します。イントロ・ノーマル・ボタンのみのすべてのモードで使用できます。

- **得点制**：正解・不正解の設定点数で採点します。
- **7○3×（ナナマルサンバツ）**：7問正解した人が勝利。3問不正解になると失格で、以降は観戦します。
- **ライフバトル**：初期ライフ3。正解すると他の全員のライフを1、不正解なら本人のライフを1減らします。0で脱落、最後の1人が勝利します。2人以上で開始します。初期ライフ・正解時のダメージ・不正解時の減少量を変更できます。不正解の減少量を0にするとライフを減らしません。

正誤判定で正解数・不正解数・ライフを更新し、回答台と運営のプレイヤータイルに表示します。同じ判定の連打は重複適用しません。現在の判定を押し直すと、ライフの減少や勝利・失格も戻して再判定します。手動の得点＋/−は点数だけを変更します。途中参加者は初期ライフで参加し、すでに終了したゲームへの参加は観戦になります。

「このラウンドをリセット」「次へ」ではゲーム全体の成績を保持します。「新しいゲーム」で全員の得点・正解数・不正解数・ライフをリセットし、最初の問題に戻ります。問題は残します。開始後にルールを変更する場合も「新しいゲーム」を使用してください。

## 問題の取り込み

CSV（UTF-8）のヘッダーは `title,answer,url,start`。日本語の `問題,答え,URL,開始秒` も対応。ノーマル問題ではurlを空にできます。イントロではYouTubeの動画URLを指定。startは開始秒です。最大500問、CSVは500KBまで。画面からCSV形式で編集できます。

Googleスプレッドシートは公開したシートURLを入力（通常の共有URLは閲覧可能な公開設定が必要）。非公開シートの認証には対応していません。gidでタブを指定できます。

YouTubeの公開・限定公開プレイリストURLから、サーバーで動画一覧とタイトルを取得します。埋め込みプレイヤーの準備は不要です。リストの続きも取得し、最大500曲まで元の順番で取り込みます。上限到達や非公開・削除済み動画の除外は画面に表示します。取得失敗時は既存の問題を保持します。非公開リスト・ログインが必要なリストには対応していません。取り込めても埋め込み再生を許可していない動画は再生できません。

通常はAPIキーなしで取得できます。YouTubeがサーバーからの取得を制限する場合やページの仕様変更で取得できない場合は、Google Cloud Consoleで「YouTube Data API v3」を有効にし、APIキーを作成してください。Renderの対象サービス → **Environment → Add Environment Variable** で `YOUTUBE_API_KEY` を設定し、保存・再デプロイすると公式APIで取得します。キーはGitやブラウザに保存・配信しません。APIキーのAPI制限は「YouTube Data API v3」に限定してください。公式APIには利用上限があります。匿名取得の仕様変更への対応も [playlist.js](playlist.js) にまとめています。

再生の自動開始はブラウザのポリシーに依存します。運営の開始ボタンを押してください。

イントロの答えは、CSV・スプレッドシート・プレイリストのどの取り込みでも動画タイトルから自動設定します。YouTube oEmbedでバックグラウンド取得し、同じ動画はキャッシュを共有します。現在の動画は運営の埋め込みプレイヤーからもタイトルを補完します。CSVのanswer列は空でも取り込めます。タイトルが取得できた場合、既存のanswerも動画タイトルで置き換えます。取得状況を運営に表示し、失敗時は再試行や手動入力ができます。自動取得中にCSV欄を編集中の場合は、その入力を上書きしません。曲名だけの抽出やアーティスト名の除去は行いません。

## 制限

参加時にサーバーが匿名の参加情報を発行し、ブラウザのlocalStorageに保存します。同じブラウザ・サイトであれば、一時的な切断、別アプリ・別タブへの移動、画面の再読み込み後も自動で元の席に戻ります。名前・部屋コードだけでは運営権限を引き継げません。匿名の参加情報は招待リンクに含めません。

切断中も運営権限・得点・正解数・不正解数・ライフ・押下順を保持します。運営が切断すると進行を一時停止し、復帰後に「再開」を押します。イントロは保持した再生位置から再開します。同じブラウザで同じ部屋を複数タブで開いても1人として扱い、最後の接続が切れるまでオンラインです。明示的に「退出」すると参加者と得点を削除し、運営の場合は接続中の参加者を優先して運営権限を渡します。退出は同じ参加情報を使う全タブに反映します。

全員が切断した部屋は12時間保持し、その後削除します。全員が明示的に退出した部屋はすぐ削除します。部屋・問題・得点・匿名セッションはメモリに保存するため、Renderの休止からの再起動・再デプロイを含むサーバー再起動で消えます。ブラウザのサイトデータ削除、別端末、別ブラウザでは自動復帰できません。1部屋30人まで（切断中の席を含む）。通信遅延を補正する競技用途、公衆向け大量アクセス、永続保存、アカウントログイン、部屋のパスワードは未実装です。

## 開発

`npm run dev` はNodeのwatchモード。`npm test` は実際のWebSocketクライアントで部屋参加、同時押下、権限、採点、タイマー、答えの公開、匿名再接続、複数タブ、切断中の席の保持を検証します。プレイリスト取得はYouTube形式の応答を使い、匿名取得・公式APIのページ送り、非公開動画、500曲上限、取得エラー・権限を検証します。フロントはビルド不要のHTML/CSS/JavaScriptです。

クラウド環境の外部通信先に `docs.google.com`, `*.googleusercontent.com`, `www.youtube.com`, `www.youtube-nocookie.com`, `s.ytimg.com`, `i.ytimg.com`, `*.googlevideo.com`, `www.googleapis.com` が必要です。設定の下書きを保存済みですが、実通信への適用・公開は環境設定側で行います。`npm start` はNode.jsの `--use-env-proxy` を使用して、既存の環境プロキシを尊重します。

## GitHubからデプロイ（Render）

`render.yaml` を同梱しています。Renderにログインして「New → Blueprint」からGitHubの `ns25350/quiz` を連携し、`main` ブランチの設定を読み込んで作成してください。作成時にプランと料金を確認してください。デプロイ先URLを参加者に共有すれば、同じサーバーの部屋へ参加できます。GitHub PagesはNode.jsサーバーを実行できないため、この構成には使えません。

ビルドで依存関係をインストールしてテストし、本番用依存関係だけを残します。Renderが割り当てる `PORT` を使用し、`/health` をヘルスチェックに使います。GitHubの `main` 更新で再デプロイするよう、Renderの自動デプロイ設定を有効にしてください。

無料プランは一定時間アクセスがないと休止する場合があり、次回の起動に時間がかかります。再起動・再デプロイで部屋は消えます。部屋の状態はメモリ保存なのでインスタンス数は1台で運用してください。複数台で運用する場合はRedisなどによる共有が必要です。
